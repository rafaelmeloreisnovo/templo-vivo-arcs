## Evidência de governança precoce

`Manifest.txt` é particularmente relevante porque, em maio de 2025, já contém requisitos explícitos de:

- respeito à autoria;
- transparência;
- comunicação de operações;
- manutenção de log auditável;
- proibição de apagar logs;
- proibição de esconder execuções.

Isso deve ser tratado como **prova documental de intenção de governança e auditabilidade**, não como prova de que todos os sistemas posteriores cumpriam automaticamente essas regras.

## Combinações que formam POCs compostos

### PC-A — Cadeia de proveniência evolutiva

`POC-04 + POC-05 + POC-07`

```text
commit/arquivo anterior
 -> referência identificada
 -> interpretação/transformação
 -> artefato derivado
 -> hash agregado + UTC + changelog
```

**Força:** demonstra que referência explícita a estado anterior, transformação e receipt aparecem antes do agente GitHub comprovado.

### PC-B — Governança declarativa + mecanismo técnico

`POC-00 + POC-06 + POC-07`

```text
regra ética/auditável
 -> invariantes em YAML
 -> mecanismo de hash/timestamp/log
```

**Força:** convergência entre norma, configuração legível por máquina e ação executável.

### PC-C — Visão → contrato → interface

`POC-03 + POC-06 + POC-08`

```text
pipeline conceitual
 -> configuração estruturada
 -> aplicação/UI
```

**Força:** demonstra trânsito entre representação abstrata e artefatos de software, ainda que a integração esteja parcial.

### PC-D — Arquitetura de obra e PI

`POC-00 + POC-04 + POC-09`

```text
governança/autoria
 -> versionamento/derivação
 -> árvore legal+técnica+documental
```

**Força:** sustenta a existência de uma arquitetura de organização da obra antes dos agentes posteriores.

## Verdadeira convergência observável

A convergência sustentada pelos artefatos não é “todos os campos provam a mesma teoria”. É mais restrita e tecnicamente defensável:

1. **Representação:** fenômenos/ideias são transformados em estados, vetores ou campos nomeados.
2. **Persistência:** estados são materializados em arquivos/commits.
3. **Identidade:** hashes/SHAs são usados como referência de estado.
4. **Temporalidade:** o tempo é tratado como dimensão do registro.
5. **Derivação:** estados anteriores alimentam novos artefatos.
6. **Governança:** regras éticas/logs/invariantes acompanham o processo.
7. **Aplicação:** parte da estrutura migra para YAML, shell, Dart e outros formatos.

Essa combinação constitui a candidata atual a **invariante arquitetural da obra**.
