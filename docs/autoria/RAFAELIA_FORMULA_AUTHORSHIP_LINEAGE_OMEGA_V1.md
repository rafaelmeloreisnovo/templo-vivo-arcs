`primitiva conhecida -> seleção -> tipagem -> composição -> parametrização -> implementação -> teste -> evidência -> claim`.

```text
fórmula escrita != definição completa != composição autoral != implementação != execução != evidência != claim científico
```

## 3. Definição operacional de estrutura autoral

Definimos, somente para governança interna e auditoria:

```text
A_struct = Select + Type + Compose + Order + Parameterize + Implement + Test + Govern
```

Isso não é fórmula jurídica universal de direito autoral. É um contrato para decompor a contribuição observável.

Para um objeto `x`, registramos:

```text
A(x) = <P, T, I, D, C_struct, X, E, F>
```

onde:

- `P`: proveniência;
- `T`: âncora temporal;
- `I`: identidade do conteúdo/artefato;
- `D`: completude da definição;
- `C_struct`: contribuição estrutural demonstrada;
- `X`: execução/reprodução;
- `E`: evidência;
- `F`: falsificador/condição de rebaixamento.

Uma ordenação conservadora pode usar:

```text
Omega_A = min(P,T,I,D) * C_struct
```

sem converter esse valor em titularidade, patenteabilidade, novidade mundial ou validade científica.

## 8. Falsificadores e rebaixamento

Qualquer claim deve ser rebaixado se ocorrer um dos seguintes:

1. fonte primária anterior contradiz a cronologia;
2. prior-art anterior demonstra a mesma contribuição específica reivindicada;
3. um operador chamado autoral for apenas uma renomeação de construção conhecida sem transformação demonstrável;
4. o arquivo atual não puder ser ligado ao estado histórico por commit/blob/path/fingerprint;
5. a identidade do agente for inferida apenas por estilo;
6. uma execução posterior for usada para retroagir capacidade histórica;
7. um resultado negativo ou limite nulo for omitido;
8. material de terceiro for incorporado sem licença/proveniência aplicável.
