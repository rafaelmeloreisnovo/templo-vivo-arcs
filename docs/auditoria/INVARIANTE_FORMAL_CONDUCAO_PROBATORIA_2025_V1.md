## Invariante de condução
`criar -> registrar -> versionar -> derivar -> estruturar -> executar -> governar -> expor ao agente -> auditar`

A propriedade preservada é continuidade verificável de estados e transformações quando existe ligação por path, commit, SHA, conteúdo, configuração, POC ou evento Git.

## Classes de prova
`E0_CLAIM -> E1_DOCUMENT -> E2_GIT_STATE -> E3_CROSS_SOURCE -> E4_CAPABILITY -> E5_REPRODUCED -> E6_INDEPENDENT`.
Nenhuma classe superior é inferida automaticamente da anterior.

## TOKEN_VAZIO / incertezas
Todo vazio deve possuir `gap_id -> claim_id -> fonte_esperada -> ação -> gate -> condição_de_falha -> próximo_estado`.

Vazios atuais: `PUSH_EVENT_EXACT`, `LINE_BY_LINE_AUTHORSHIP`, `NOVOEXPORT_FIRST_KNOWN`, `TAG_HISTORICAL_ENUMERATION`, `C5_HISTORICAL_REPRODUCTION`, `PRIOR_ART`.

## Não regressão
Passagem do tempo, repetição narrativa e parábola não preenchem evidência; extensão de arquivo não prova execução; commit não equivale automaticamente a push; conta Git não equivale automaticamente a autoria intelectual integral; conflito novo suspende o claim dependente; promoção exige `evidence_delta > 0`.

## Invariante formal
Para claim `q`: `S(q) = min(T,P,I,C,F) * K`, com T=tempo, P=proveniência, I=integridade, C=capacidade, F=falsificabilidade e K=convergência comprovada. O elo essencial mais fraco limita a promoção.

## Claim sustentável
`PRE_AGENT_MATERIALIZATION = SUPPORTED_LIMITED`.

Não implica `WORLD_FIRST`, `NO_AI_ASSISTANCE_EVER`, `PATENT_GRANTED`, `SCIENTIFIC_VALIDATION` ou `EXACT_PUSH_TIME`.
